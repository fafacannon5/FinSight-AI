# 怎么用这个框架（给 Jing 和 Haiyan）

Cursor、Codex 和 Claude Code 都会在开始时读 `AGENTS.md`（Claude Code 通过 `CLAUDE.md` 读取），
所以三种工具的用法相同：在仓库根目录打开，直接用下面的话开头。

| 你想做什么 | 对 AI 说 | AI 会做什么 |
|---|---|---|
| 不知道下一步 | "我是 J，下一步做什么？" / "guide" | 检查代码和测试 → 给出一个具体任务 → 在对应函数里写提示（默认第 2 级） |
| 提示太少 / 太多 | "更多提示" / "更难" | 把这个函数的提示调简单一级或难一级 |
| 让它直接写完 | "写完整代码" | 写完整实现，然后给你讲解，你要能自己讲清楚 |
| 检查代码 | "测试" / "run tests" | 跑 `pytest`，用白话解释失败原因，默认只给提示不直接改 |
| 跑实验 | "帮我跑 E1，nprobe=16" | 写 YAML 配置 → 运行 → 把结果写进 wiki |
| 看不懂 | "讲解 TorchKNN" / "考考我" | 讲原理、对应课程哪一周、举手算例子、出 3 道题 |
| 合并前检查 | "review my code" | 检查正确性、测试集泄漏、比较是否公平 |
| 合并到 main | "提 PR" / "合并" / "同步 main" | 跑合并前检查清单，一步步给你命令，帮你解释和处理冲突。push 和 merge 由你自己执行 |

规则：
- 每完成一个带"merge"标记的里程碑就合并一次，不要等到最后（详见 `agents/workflow/merge.md`）。PR 由对方 review，再由对方点合并。
- 第一次下载模型或数据集之前（M2、M3、M9），AI 会先讲清楚：下载的是什么、从哪来、为什么需要、多大、存在哪、怎么确认成功，等你说"好"才运行。
- AI 不会自己 commit 或 push。它会提醒你提交，并给出建议的 commit 信息，什么时候提交由你决定。
- 默认把使用者当作 **Jing (J)**。Haiyan 用的时候，开头说一句"我是 H"。
- 测试集是锁住的。只有说"跑测试集 / final evaluation"，而且 `wiki/decisions/final_configs.md` 已经写好，AI 才会动它。
- AI 帮忙写的代码，建议的 commit 信息里会带上 `Assisted-by:`，并记录在 `AI_USAGE.md`，这是课程政策要求的。
- 一开始 `pytest` 全部失败是正常的：函数都还是空的，测试规定了它们应该做什么。按里程碑 M1 → M12 逐个变绿。
