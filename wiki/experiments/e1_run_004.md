# E1 run 004 — IVF with nprobe = 4

Source: `experiments/results/run_e1_004/metrics.json`.

## Hypothesis

`faiss_ivf` with `nprobe = 4` recovers most of the accuracy loss — within 5 points of exact search —
at a fraction of the latency.

## Config diff vs run_e1_003

One factor changed: `nprobe: 1` → `nprobe: 4`. `nlist` stays 240.

## Metrics (57,638 docs, 500 queries, dim 384)

| Metric | run 001 (exact) | run 004 (nprobe 4) | Gap |
|---|---|---|---|
| Recall@5 | 0.3797 | 0.3065 | −7.32 pt |
| Recall@10 | 0.4665 | 0.3734 | **−9.32 pt** |
| MRR@10 | 0.4532 | 0.3614 | −9.18 pt |
| nDCG@10 | 0.3881 | 0.3063 | −8.19 pt |
| latency mean | 0.6704 ms | 0.0276 ms | 24.3× faster |
| latency p95 | 0.7674 ms | 0.0356 ms | 21.5× faster |
| build time | 0.00053 s | 0.1809 s | — |

## Verdict

**Rejected.** The gap is 9.32 points, not the predicted ≤5. Going from 1 to 4 cells recovers about
half the loss (−18.35 → −9.32 pt) while latency roughly doubles (0.0153 → 0.0356 ms p95): accuracy
is bought back at a worsening exchange rate in this region of the curve.

## Next step

Push `nprobe` further; the interesting question is where the curve flattens.
