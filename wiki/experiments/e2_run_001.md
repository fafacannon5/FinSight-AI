# E2 run 001 — PCA 128-d

Source: `experiments/results/run_e2_001/metrics.json`.

## Hypothesis

PCA to 128-d keeps Recall@10 within 1 point of 384-d while cutting index memory 3x

## Config

`experiments/configs/run_e2_001.yaml` — FiQA `dev`, `torch_knn` (exact), `pca_dim` 128, k 10,
`latency_queries` 200, seed 42. PCA fit on the corpus only; queries transformed with the corpus mean (Hard rule 2).
Variance kept by 128 components (corpus-only check, M7): 0.795.

## Metrics (57,638 docs, 500 queries, dim 128)

| Metric | Value | vs run 000 |
|---|---|---|
| Recall@5 | 0.3555 | -2.42 pt |
| Recall@10 | 0.4412 | -2.54 pt |
| MRR@10 | 0.4184 | -3.48 pt |
| nDCG@10 | 0.3586 | -2.95 pt |

## Verdict

**Rejected (narrowly).** Recall@10 drops 2.54 pt, not ≤ 1 pt. Memory is cut 3× as predicted; p95 is 2.6× faster.
