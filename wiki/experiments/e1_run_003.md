# E1 run 003 — IVF with nprobe = 1

Worst case of approximate search: the query is compared only against the single nearest cell.
Source: `experiments/results/run_e1_003/metrics.json`.

## Hypothesis

`faiss_ivf` with `nprobe = 1` loses more than 15 points of Recall@10 against exact search.

## Config diff vs run_e1_002

`method: faiss_flat` → `method: faiss_ivf`, `method_params: {nlist: 240, nprobe: 1}`
(`nlist ≈ √57,638 ≈ 240`).

## Metrics (57,638 docs, 500 queries, dim 384)

| Metric | run 001 (exact) | run 003 (nprobe 1) | Gap |
|---|---|---|---|
| Recall@5 | 0.3797 | 0.2391 | −14.06 pt |
| Recall@10 | 0.4665 | 0.2831 | **−18.35 pt** |
| MRR@10 | 0.4532 | 0.2947 | −15.85 pt |
| nDCG@10 | 0.3881 | 0.2387 | −14.94 pt |
| latency mean | 0.6704 ms | 0.0119 ms | 56.4× faster |
| latency p95 | 0.7674 ms | 0.0153 ms | 50.0× faster |
| build time | 0.00053 s | 0.1881 s | K-means training |
| index memory | 84.43 MB | 84.43 MB | identical |

## Verdict

**Confirmed.** Recall@10 drops 18.35 points, more than the predicted 15.

## Notes

- 50× faster but nearly 40% of the relevant documents are missed — the extreme point of the curve,
  useful mainly to show the trade-off has a real cost at the cheap end.
- Build time 0.188 s: this is the first run where index construction costs something (K-means on
  57,638 vectors into 240 cells).
