# E2 run 002 — PCA 64-d

Source: `experiments/results/run_e2_002/metrics.json`.

## Hypothesis

PCA to 64-d keeps Recall@10 within 3 points of 384-d while cutting index memory 6x

## Config

`experiments/configs/run_e2_002.yaml` — FiQA `dev`, `torch_knn` (exact), `pca_dim` 64, k 10,
`latency_queries` 200, seed 42. PCA fit on the corpus only; queries transformed with the corpus mean (Hard rule 2).
Variance kept by 64 components (corpus-only check, M7): 0.614.

## Metrics (57,638 docs, 500 queries, dim 64)

| Metric | Value | vs run 000 |
|---|---|---|
| Recall@5 | 0.2793 | -10.04 pt |
| Recall@10 | 0.3671 | -9.94 pt |
| MRR@10 | 0.3490 | -10.42 pt |

## Verdict

**Rejected.** Recall@10 drops 9.94 pt, far beyond the 3 pt budget, for 6× less memory and 3.9× faster p95.
