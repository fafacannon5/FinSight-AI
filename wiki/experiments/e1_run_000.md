# E1 run 000 — SciFact smoke test

Milestone M5. SciFact is the **debug** dataset: this run exists to prove the pipeline works, and these
numbers are **never reported** in the final results (the config comment and `overview.md` both say so).

Source of every number below: `experiments/results/run_e1_000/metrics.json`.

## Hypothesis

The end-to-end SciFact retrieval pipeline (BEIR load → MiniLM embeddings → `TorchKNN` → metrics)
runs successfully and produces valid retrieval metrics.

## Config

`experiments/configs/run_e1_000_scifact_smoke.yaml` — dataset `scifact`, split `test`, method
`torch_knn`, `pca_dim` null, `k` 10, `latency_queries` 100, `random_seed` 42.
First run, so there is no config diff against a previous run.

## Acceptance checks (M5)

1. Runs without error and writes `metrics.json` → **pass**
2. All metrics finite and inside `[0, 1]` → **pass**
3. `Recall@10 ≥ Recall@5` → 0.7833 ≥ 0.7379 → **pass**
4. Far above a random-ranking baseline → random Recall@10 ≈ 0.00218
   (339 relevant pairs over 300 queries, 5,183 docs, k = 10); observed is **359×** the baseline → **pass**

## Verdict

**Confirmed.** The pipeline is valid; E1 can move to the real dataset.

## Observations to carry into FiQA

- `build_time_s = 0.00038` is not a real number for `TorchKNN` — the exact index does no preprocessing,
  so `fit` is only a tensor copy. Build time becomes meaningful for `FaissIVF` and `KMeansIndex`
  (K-means training), and that is where it belongs in the report.
- `index_memory_mb = 7.59` = 5183 × 384 × 4 / 2²⁰ — pure payload, no index overhead. Same for
  `FaissFlat`; IVF and K-means add centroids and inverted lists.
- Latency is measured on single queries with warm-up excluded (100 of the 300 queries).
  FiQA has 57,638 docs ≈ 11× SciFact, so expect `torch_knn` latency to scale roughly linearly.
- Only queries with qrels are kept (300 of SciFact's 1,109), which is why `n_queries` is 300.
