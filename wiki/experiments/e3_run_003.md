# E3 run 003 — τ for config B

**Hypothesis:** PCA changes the cosine scale, so τ = 0.60 (tuned at 384-d, [run 002](e3_run_002.md)) does not
transfer to 128-d; B needs its own τ.

**Config:** same as run 002 (FiQA dev, corpus minus the 116 removed docs, 450 answerable vs. the 10 verified
unanswerable, τ 0.30–0.90 step 0.01, pick max of (answer rate + correct-refusal rate) / 2, ties → smaller τ),
but with PCA 128-d fitted on the indexed corpus and `faiss_ivf` {nlist 240, nprobe 16}.
Script: `scripts/e3_tau_config.py`. Sanity check: the same script for config A reproduces run 002 exactly
(τ 0.60, AUC 0.823, Recall@10 0.4684).

## Results

| Config | Recall@10 (answerable, reduced corpus) | Median top-1: answerable / unanswerable | AUC | Best τ | Answer rate | Correct refusal |

## Verdict: confirmed

- PCA raises every cosine (medians +0.03), so B's τ is higher: **0.66**. Using A's 0.60 on B would answer
  84 % but refuse only 6 of 10 unanswerable questions.
- Separation is unchanged (AUC 0.823 vs. 0.826): PCA + IVF shifts the scores but does not hurt refusal.
- B's curve is jumpy with only 10 unanswerable questions: τ 0.58 is nearly as good (balanced 0.748) and
  answers far more. We keep the pre-set rule (max balanced) rather than picking by eye.

## Caveats

Same as run 002: 10 verified unanswerable questions, τ chosen on them. Here PCA is fitted on the reduced
corpus (57,522 docs); in run_e2_004 and on test it is fitted on the full corpus — a negligible difference.
